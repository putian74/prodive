# C++/CUDA KL-divergence computation

This directory contains the GPU implementation used by ProDive to compute pairwise fragment-level KL-divergence matrices from a packed HHM fragment database.

## Position in the pipeline

This stage follows HHM preprocessing and packed-database construction:

```text
data_preparation/scripts/02_pack_hhm_fragments.py
    -> packed fragment database
src/cpp_cuda/kl_divergence
    -> dense KL matrices and run manifest
src/path_extraction/scripts/01_filter_cpp_kl_results.py
    -> sparse filtered pickle files
```

## Build

```bash
make clean
make -j
```

Dependencies:

```text
CUDA toolkit
C++ compiler with C++14 support
Eigen headers
zlib
```

The bundled `Makefile` uses:

```text
-arch=sm_86
```

This setting is appropriate for NVIDIA Ampere GPUs. For other GPU generations, modify `NVCC_FLAGS` before compiling.

## Input packed database

The packed database should be generated by:

```text
data_preparation/scripts/02_pack_hhm_fragments.py
```

Required files:

```text
metadata.json
index.csv
pi_all.float32.bin
A_all.float32.bin
B_all.float32.bin
```

Runtime constants are read from `metadata.json`, including:

```text
fragment
m_states
n_obs
num_datasets
min_frag
max_frag
```

The current C++/CUDA implementation reads packed arrays as `float`. Packed `float64` files are not supported by this stage.

## Range mode

Range mode computes all intended pairs inside the requested numeric ID ranges. With default symmetric reconstruction, the upper-triangular pair set is queued.

```bash
./kl_divergence \
  --start_i 0 --end_i 100 \
  --start_j 0 --end_j 100 \
  --packed_db /path/to/fragment_6_packed \
  --memory_efficient \
  --num_streams 8 \
  --max_gpus 4 \
  --outdir /path/to/kl_output
```

## Pair-list mode

Pair-list mode computes only explicitly listed numeric record-ID pairs.

```bash
./kl_divergence \
  --pair_list /path/to/pairs.csv \
  --packed_db /path/to/fragment_6_packed \
  --memory_efficient \
  --num_streams 8 \
  --max_gpus 4 \
  --outdir /path/to/kl_output
```

Accepted pair-list formats:

```text
0,1
2,5
```

or:

```text
i,j
0,1
2,5
```

The pair list uses numeric HHM record IDs from the preprocessing mapping file, not HHM filenames.

## Output

The default output format is NPY:

```text
kl_0000_0001.npy
```

Use `--save_text` only for small debugging runs.

Each run also writes a run manifest and completion marker.

Range mode writes:

```text
prodive_run_manifest.json
prodive_computed_ranges.csv
RUN_COMPLETE
```

Pair-list mode writes:

```text
prodive_run_manifest.json
prodive_computed_pairs.csv
RUN_COMPLETE
```

`RUN_COMPLETE` is written only after successful completion. If an expected matrix is missing at the end of the run, the program writes `prodive_missing_outputs.csv`, marks the manifest as failed, and returns a non-zero exit code.

The downstream filtering stage uses `prodive_run_manifest.json` and `RUN_COMPLETE` to validate the C++ output directory. It should not infer the expected pair set only by scanning existing `kl_*.npy` files.

## Runtime capacity

The CUDA kernels use compile-time safety capacities in `kl_divergence.h`:

```cpp
constexpr int MAX_M_STATES = 64;
constexpr int MAX_N_OBS = 32;
```

For fragment length `k`, the state count is `3*k+1`. Larger fragment lengths require increasing `MAX_M_STATES` and recompiling.

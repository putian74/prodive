# C++/CUDA KL-divergence computation

This directory contains the GPU implementation used by ProDive to compute pairwise fragment-level KL-divergence matrices from a packed HHM fragment database.

## Role in the workflow

The C++/CUDA executable operates on the packed fragment database generated during data preparation and produces dense KL-divergence matrices for downstream filtering:

```text
data_preparation/scripts/02_pack_hhm_fragments.py
    -> packed fragment database
src/cpp_cuda/kl_divergence
    -> dense KL matrices and run manifest
src/path_extraction/scripts/01_filter_cpp_kl_results.py
    -> sparse filtered pickle files
```

## Build

```bash
make clean
make -j
```

Dependencies:

```text
CUDA toolkit
C++ compiler with C++14 support
Eigen headers
zlib
```

The bundled `Makefile` uses:

```text
-arch=sm_86
```

This setting targets NVIDIA Ampere GPUs. For other GPU generations, modify `NVCC_FLAGS` before compiling.

## Input packed database

The packed database is generated by:

```text
data_preparation/scripts/02_pack_hhm_fragments.py
```

Required files:

```text
metadata.json
index.csv
pi_all.float32.bin
A_all.float32.bin
B_all.float32.bin
```

Runtime constants are read from `metadata.json`, including:

```text
fragment
m_states
n_obs
num_datasets
min_frag
max_frag
```

The implementation reads packed arrays as `float`. The recommended packed-array dtype is `float32`.

## Range mode

Range mode computes pairs within requested numeric ID ranges. With symmetric reconstruction enabled, the upper-triangular pair set is queued for a square range.

```bash
./kl_divergence   --start_i 0 --end_i 100   --start_j 0 --end_j 100   --packed_db /path/to/fragment_6_packed   --memory_efficient   --num_streams 8   --max_gpus 4   --outdir /path/to/kl_output
```

## Pair-list mode

Pair-list mode computes explicitly specified numeric record-ID pairs.

```bash
./kl_divergence   --pair_list /path/to/pairs.csv   --packed_db /path/to/fragment_6_packed   --memory_efficient   --num_streams 8   --max_gpus 4   --outdir /path/to/kl_output
```

Accepted pair-list formats:

```text
0,1
2,5
```

or:

```text
i,j
0,1
2,5
```

The pair list uses numeric HHM record IDs from the preprocessing mapping file.

## Output

The default matrix output format is NPY:

```text
kl_0000_0001.npy
```

Text output can be enabled with `--save_text` for small diagnostic runs.

Each completed run writes a manifest and completion marker.

Range mode writes:

```text
prodive_run_manifest.json
prodive_computed_ranges.csv
RUN_COMPLETE
```

Pair-list mode writes:

```text
prodive_run_manifest.json
prodive_computed_pairs.csv
RUN_COMPLETE
```

If an expected matrix is missing at the end of the run, the program writes `prodive_missing_outputs.csv`, records failure information in the manifest, and returns a non-zero exit code.

## Runtime capacity

The CUDA kernels use compile-time safety capacities defined in `kl_divergence.h`:

```cpp
constexpr int MAX_M_STATES = 64;
constexpr int MAX_N_OBS = 32;
```

For fragment length `k`, the state count is `3*k + 1`. Fragment lengths that require larger state arrays should be configured by increasing `MAX_M_STATES` and recompiling.

## Common options

```text
--packed_db PATH       packed fragment database directory
--outdir PATH          output directory
--start_i N            first numeric ID in the i-range
--end_i N              end of the i-range, exclusive
--start_j N            first numeric ID in the j-range
--end_j N              end of the j-range, exclusive
--pair_list PATH       explicit pair list for pair-list mode
--memory_efficient     load only required datasets
--num_streams N        CUDA streams per GPU
--max_gpus N           maximum number of GPUs to use
--resume               skip existing expected output files
--no_symmetric         disable symmetric reconstruction in range mode
```

# ProDive

ProDive is a computational framework for detecting local relationships between profile hidden Markov models (profile HMMs). This repository contains the code associated with two complementary parts of the project: the core ProDive method and the downstream fragment-level analyses.

## Repository structure

| Directory | Description |
| --- | --- |
| [`prodive/`](prodive/) | Core ProDive implementation, including profile-HMM preprocessing, GPU-accelerated symmetric KL-divergence calculations, multi-stage filtering, path construction, parameter analyses, and computational benchmarking. |
| [`prodive-fragment-analysis/`](prodive-fragment-analysis/) | Downstream analyses and validation of the detected local fragments, including structural comparisons, community detection, secondary-structure and solvent-accessibility analyses, disorder analyses, 3did interface comparisons, ESM2 analyses, and φ-value comparisons. |

Each directory contains its own `README.md` with module-specific dependencies, input requirements, commands, parameters, and output descriptions.

## Data availability

The input resources and precomputed results used by both parts of the project are available from Zenodo:

**https://doi.org/10.5281/zenodo.20838915**

The Zenodo archive contains the shared data layout referenced by the two code modules. Some large intermediate products, such as locally generated packed databases and GPU matrix outputs, must be regenerated by following the instructions in the relevant subdirectory.

## Getting started

1. Download and extract the Zenodo data archive.
2. Choose the relevant code module:
   - use `prodive/` to reproduce the core detection workflow and benchmarks;
   - use `prodive-fragment-analysis/` to reproduce downstream fragment analyses and validation.
3. Follow the detailed setup and execution instructions in that module's `README.md`.

A typical local layout is:

```text
project_root/
├── ProDive_release/
│   ├── data/
│   └── precomputed_results/
├── prodive/
└── prodive-fragment-analysis/
```

The two code modules share the released data but represent separate workflows. They should be configured and run according to their own documentation.

## Reproducibility notes

- Published precomputed results can be used to inspect and reproduce downstream analyses without rerunning every computationally intensive stage.
- Full regeneration of the core search requires the additional intermediate files described in `prodive/README.md`.
- Analyses requiring Pfam seed structures should follow the structure-archive README to construct the expected runtime directory.
- Software dependencies and module-specific parameters are documented separately in each code directory.
